荣耀电源刷新率钩子 · 三层归属

系统事件、自装工具、厂商私有组件分属三方，彼此并不知道对方存在，靠任务定义与 P/Invoke 硬接起来。

1 · Windows 系统自带

系统提供，不依赖本工程
Kernel-Power 105内核写入 System 日志
Task Scheduler订阅事件并启动进程
Win32 API读供电状态与刷新率
这一层到底是什么

Microsoft-Windows-Kernel-Power 是内核电源管理器的事件日志提供程序，把电源状态变化写进 System 日志。EventID 105 的消息是「电源更改。」，本机实测由 ProcessID=4（System 进程）、S-1-5-18（LOCAL SYSTEM）发出，附带 AcOnline=true、RemainingCapacity、FullChargeCapacity。

它是一条既成事实的记录，不是回调、不会调用任何程序。系统日志里 Kernel-Power 还有 566、507、506、521、109、42、107 等诸多 ID，105 只是 AC/DC 切换那一种。事件本身带 AcOnline，但本工具没有读事件数据，而是启动后自己调 GetSystemPowerStatus。

Task Scheduler 服务与 GetSystemPowerStatus / EnumDisplaySettingsEx 都是微软提供的系统能力；.NET Framework CLR 与系统自带编译器同样属于这一层。

本工程实际产出的东西
  • 计划任务定义 \HonorPowerRefreshHook：由安装脚本手写 XML 注册，含 Kernel-Power 105 事件触发器与登录触发器。这是一条配置，不是程序。
  • HonorPowerRefresh.cs 及其编译产物 HonorPowerRefresh.exe：一次性 C# 程序，负责策略与校验。
  • build.ps1、Install-HonorPowerRefresh.ps1、Remove-HonorPowerRefresh.ps1、HonorPowerRefresh.config.ini、HonorPowerRefresh.log、说明文档与本网页。

执行链：等 750ms → 读 AC/电池 → 定目标 120/60 Hz → 已是目标则退出 → 枚举可用档位 → 调 ChangeFrequency → 读回验证。不常驻、不改注册表或服务、不装驱动；exe 未签名，位于用户可写目录。

3 · 荣耀 OEM 私有组件

PC Manager / OSD
HardwareHal.dllHardware Abstract Layer
ChangeFrequency命名导出，序号 2
Fn+R 热键与工具同一入口
这一层不是 Windows API

文件 C:\Program Files\HONOR\OSD\HardwareHal.dll，版本信息为 Honor Device Co., Ltd. / Hardware Abstract Layer / PC Manager 1.0.0.1。解析 PE 导出表：PE32+ x64，Base=1，20 个函数 / 20 个命名导出，ChangeFrequency 是真实的命名导出（序号 2，函数 RVA 0xBBC0），同表还有 HalInit、SetMic、SetVolume、SetScreen 等硬件抽象层接口。

源码声明：[DllImport(..., EntryPoint="ChangeFrequency", CallingConvention=Cdecl)] int ChangeFrequency(ref int afterHz, ref int beforeHz)，返回 1 表示成功，两个引用参数回传切换前后的 Hz。内部实现未逆向；从「循环调用 + 读回验证」的写法推断，它在硬件支持的档位间轮转。源码注释写明与荣耀 Fn+R 走同一个导出。

Windows 切刷新率的标准做法是 user32!ChangeDisplaySettingsEx，本工具没走那条路，而是借厂商 HAL。这是未文档化的私有接口，管家/OSD 更新改掉导出名或档位行为，工具会静默失效。

只有第 2 层是我们写的吗

是，只有第 2 层是本工程产出的。第 1 层是 Windows 既有能力，第 3 层是荣耀既有组件；我们既没有写内核事件，也没有写厂商 DLL，只做了「订阅」和「调用」这两处接线。

三点限定：① 第 2 层的「任务订阅」是我们创建的一条 XML 配置，不是代码，底层机制仍属系统；② exe 依赖系统 .NET CLR 与系统自带编译器，工程里不含运行时；③ 图里两根箭头（事件订阅、P/Invoke）代表的是我们写的关系，不属于第 1 或第 3 层。

换句话说：系统只是广播了一条日志，工具把日志当闹钟，再借厂商的私有函数去拧硬件。跑一遍卸载脚本注销任务后，Windows 与荣耀管家的行为一切照旧。
